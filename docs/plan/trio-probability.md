# 三連複の確率モデル・買い目選択の検討（2026-10-12）

> このファイルは探索・議論の場です。決定前のアイデアや選択肢を自由に書いてください。
> 確定した仕様は `spec.md` に移してください。

---

## 発端

メインで賭けるのは三連複なのに、現行モデルは「1着」を中心に作られており、3着内の組み合わせ確率を正確に予想できていないのではないか、という問題意識。
最終的には「三連複を複数点買うとき、どの買い目をどう組み合わせると期待値が高いか」を出したい。

## 責務の整理（2026-10-17）

- このモデル（predictor）の責務は**各馬の着順確率をできるだけ正確に出すこと**。市場オッズとの折衷と、どの買い目を買うかの判断は**別の LLM** が担っている。
- 確率が理想的に正確なら、人気薄の1着予想だけを選んで買うといった選択的な買い方で回収率は上がる。だからモデル側は精度を重視する。
- したがって、以下のフェーズのうち EV ゲート（フェーズ3）と多点配分（フェーズ4）、「市場＋モデル」の検定は、このモデルの責務から外す。オッズの取得（フェーズ0）は LLM 側の判断材料として続ける。

## 現状の整理

| 要素 | 現状 | 三連複から見た問題 |
|---|---|---|
| 勝ちモデル | lambdarank（`label_gain` 線形）→ softmax → isotonic 較正 | ハイパーパラメータは win_logloss 最小化でチューニング（ADR-0012）。2〜3着の精度は最適化対象外 |
| 複勝モデル | binary（`is_placed`）→ isotonic 較正 | 学習済みだが **三連複確率には使われていない**（複勝推奨のみ） |
| 三連複確率 | `win_prob` だけを Plackett-Luce MC に入れて算出（`output.py`） | PL は「勝ちやすさ＝2着・3着の入りやすさ」を仮定。実際には人気薄の2〜3着確率を過大評価しやすい（Harville バイアス） |
| 三連複バックテスト | `ev_trio_bootstrap_ci`: 1位馬の**単勝EV**が閾値超えなら上位3頭を1点買い | 三連複そのものの EV で選んだことは一度もない |
| 三連複オッズ | 未収集（`pre_race_odds` は単勝のみ、`payoffs` は的中組の払戻のみ） | 外れ組のオッズが無く、買い目ごとの EV を計算できない → フェーズ0で単勝オッズから推定 |

ADR-0009 / ADR-0029 で三連複が Rejected になったのは「単勝 EV で三連複を買う」戦略の判定であり、**三連複を正しく確率化・EV化した戦略は未検証**と言える。

## 基本方針

1. 期待値は加法的なので、買い目セットの EV＝各買い目の EV の和。**組み合わせ最適化より先に「1点ごとの三連複確率」と「三連複オッズ」を正確にする**。
2. 評価指標は回収率の前に **三連複対数尤度**（各レースの実際の3着内セットにモデルが付けた確率の −log）を使う。回収率よりずっと低分散で、改善の有無を検定しやすい。
3. 判定は CLAUDE.md の運用ルール6に従い、walk-forward ＋ レース単位の paired bootstrap CI で行う。

## フェーズ

### フェーズ0: 三連複オッズの取得（JRA 2008年以降）

取得コストを調査した結果（2026-10-12）、JRA は過去分を取り直せる見込み。下の「推定」案は、取得できない範囲（地方、2007年以前）の予備とする。

- API: 単勝と同じ `race.netkeiba.com/api/api_get_jra_odds.html` に `type=7` を指定すると、**1リクエストで三連複の全組み合わせ**が返る（16頭立てで560組、約22KB）。`data.odds["7"]` の値は `[オッズ, _, 人気, 馬番3頭（0埋め2桁×3）]`。
- 中身は確定オッズ: 201906050901 の的中組 1-12-14 が API では 51.4、`payoffs` では 5,140円で一致。
- 取得できる期間: 2007年12月以降は取得可。2007年6月以前は `status: NG, reason: empty free odds schedule` で取得不可。
- 対象: DB 上の JRA 2008年以降 約3.4万レース。リクエスト間隔3秒で約29時間。
- 地方: `nar.netkeiba.com/api/api_get_nar_odds.html` に同じパラメータを渡すと、別形式（`ary_odds`）の単勝オッズしか返らない。三連複の取り方は要調査。対象は約14万レース（約5日）。地方でも三連複を買うかどうかで要否を決める。
- 保存案: `trio_odds(race_id, combination, odds)` の行形式。合計1,000万行台の見込み。
- 今後のレース: 確定オッズをスケジューラで毎回取得し、実運用の EV 計算用に発走前のスナップショットも別途取る。

### フェーズ0（予備）: 三連複オッズの推定（取得できない範囲用）

過去の全レース分の三連複オッズを取り直すのは負担が大きすぎるため、**単勝オッズから推定する**（2026-10-12）。

- 推定手順:
  1. 単勝オッズから市場の勝率を逆算する: q_i ∝ 1/単勝オッズ_i をレース内で合計1に正規化（控除率を除去）。
  2. q を PL に入れて市場の三連複確率 p_market を出す。
  3. 推定オッズ ≈ 払戻率 / p_market（JRA 三連複は 75%。地方は主催者ごとに確認）。
  4. 補正: 素の Harville/PL 推定は人気薄を含む組でズレやすい。`payoffs` にある**的中組の実配当**（1レース1組×全過去レース）を使い、「推定オッズ→実オッズ」の補正（人気の組み合わせ、頭数などを説明変数にした回帰、または Henery 型ディスカウント）を学習する。
- 補正学習の注意: サンプルが的中組だけなので、市場で過剰に売れた組（実オッズ<推定）が多めに入り、補正は安め＝EV を低めに見積もる方向に偏る。甘くなる方向ではないので許容する。
- バックテストの誠実さ: 推定オッズは**買い目の選択だけ**に使い、回収額は `payoffs` の実配当で計算する。推定が外れても成績が水増しされることはなく、選択の精度が落ちるだけ。
- 限界: 推定オッズで捉えられるのは市場の**系統的な**ズレ（人気薄の組が売れすぎ等）だけで、レース固有のズレは見えない。三連複にしかないエッジの一部は取りこぼす。系統的なズレだけで 100% を超えれば十分。超えなかった場合に、実際の三連複オッズの収集を再検討する。
- 推定の検証用に、今後のレースの三連複オッズだけ少量収集する（netkeiba の三連複オッズ API で全組み合わせが1リクエストで取れるか調査）。遡るとしても直近1〜3か月に限る。全組み合わせについて推定の当たり具合を確かめるのが目的。

### フェーズ1: 現状の三連複確率の診断

- 指標: 三連複対数尤度、P(3着内) の較正曲線（PL から出した周辺確率と、複勝モデルの `place_prob` の両方）。
- 比較対象:
  - (a) 現行: `win_prob` → PL
  - (b) 複勝モデルの `place_prob` 単体の較正
  - (c) 三連複オッズから逆算した市場の暗黙確率（フェーズ0でオッズが取れた場合）。**モデルが (c) に勝てるかが本当のエッジの有無**
- (a) の P(3着内) 周辺確率が `place_prob` より明確に較正が悪ければ、仮説「win ベースでは3着内を正確に予想できない」が裏付けられる。
- **馬同士の連動（残差相関）の検定**: 各馬の確率を固定したうえで、同じ脚質（先行指数で分類）の馬が一緒に3着内に来る頻度が PL の予測より有意に多いかを bootstrap で検定する。有意差がなければ案D（展開シナリオ混合）は不要。
  - 背景: PL は「ある馬が崩れた分の確率は残りの全馬に強さの比率どおりに配られる」と仮定する。実際には、ハイペースなら差し馬がまとめて浮上する、前残りの馬場なら先行馬がまとめて残る、といった連動がある。結果には3着内に入らなかった馬（ペースを作った逃げ馬など）も影響している。
  - ペースの**予想**分はレース内ペース特徴量（ADR-0021）で各馬の確率に反映済み。反映できていないのは、実際のペースや馬場が予想からどれだけ外れるかの幅。

### フェーズ2: 3着内の同時確率を改善する

#### 位置づけ（何を学習し、何を学習しないか）

- **買い目の組み合わせ方（何点・どれを・いくら）は学習しない**。EV は加法的なので、1点ごとの EV が正しければ選択・配分はフェーズ4のルール（EV 閾値＋多点ケリー）で決まる。
- **改善の主役は各馬の3着内率（周辺確率）の精度**。
- ただし周辺確率だけでは三連複確率（同時確率）は一意に決まらない。例: 5頭立てで全馬の3着内率が60%でも、「全10通りが各10%」と「{ABC}{BCD}{CDE}{DEA}{EAB}の5通りが各20%」のどちらとも整合し、{ABD} は 10% と 0% で異なる。
- そのため周辺確率→同時確率の変換に、PL 型の構造モデルを使う（下表の A・B）。馬同士の相関（ペースで先行馬が共倒れ等）まで捉える「組み合わせの直接学習」（C）は二次的な効果とみて後回し。

軽い順に試し、フェーズ1の指標で比較する。

| 案 | 内容 | 工数 |
|---|---|---|
| A. 着順別ディスカウント（Benter/Henery 型） | 2着・3着の選択では強さを `win_prob^λ2`, `win_prob^λ3`（λ<1）に平らにする。λ は学習データで最尤推定 | 小（パラメータ2つ） |
| B. 複勝モデルとの整合 | PL の周辺 P(3着内) が `place_prob` に一致するよう各馬の強さを反復調整し、勝ち・複勝の2モデルの情報を同時確率に統合 | 中 |
| D. 展開シナリオ混合 | ペース（スロー／平均／ハイ）などの全馬に共通する要因でシナリオを分け、シナリオごとに強さを変えた PL を確率で重み付けして混ぜる。馬ごとにばらばらに揺らすのではなく共通要因を揺らすことで、馬同士の連動が生まれる。フェーズ1の残差相関検定が有意だった場合のみ | 中〜大 |
| C. 3着内を直接学習 | lambdarank の `label_gain` を3着内重視に変える／Top-3 の PL 尤度を目的関数にする／1・2・3着の多クラス出力 | 大 |

A と B は既存モデルの再学習が不要で、MC の前段に差し込むだけ。まず A→B で効果を見て、頭打ちなら C に進む。

#### 案Dの具体化: 2段階生成モデルと what-if 探索

「逃げ馬のうちどれが崩れるとどうなるか」を複数通り探索したい、という要望（2026-10-12）。

- 現行 PL のまま「X が3着外」で条件付けしても、X の確率が残りの全馬に強さの比率どおりに配られるだけで、「X が崩れた＝ペースが速かった＝差し馬が浮上」という連動は出ない。
- そこでレースを2段階で生成する。
  1. **前半シナリオ**: 誰がハナを取るか（第1コーナー1番手）、ハナ争いの有無、実際のペース水準。
  2. **前半を条件にした着順**: 前半の結果（自馬の位置取り、実際のペース、ハナを取った馬の脚質など）を入力に加えたモデルで各馬の強さを出し、PL で着順を引く。
- 学習時は前半の情報（レース後に分かる実績値）を入力に使う。予測時は前半をユーザーが指定するか、前半シナリオモデルから確率で引くので、リークにはならない。
- データ:
  - ハナを取った馬: `passing_order` の第1コーナー位置から分かる。
  - 実際のペース: `finish_time − last_3f` で前半タイムを近似し、コース・距離・馬場ごとに偏差値化（粗い近似）。
  - ラップタイム・ペース（前半3F・後半3F）が `races.raw_data` に含まれているか要確認。無ければレース結果ページから追加取得を検討。
- 使い道は2つ:
  1. **what-if ツール（人が使う）**: 「X がハナ」「X と Y が競り合ってハイペース」などのシナリオを指定し、シナリオごとの三連複確率と浮上する買い目を並べて表示する。前半を条件にした着順の当たり具合（三連複対数尤度）さえ確認できれば、回収率のゲート判定を通さなくても判断材料として使える。
  2. **自動 EV**: 前半シナリオモデルからシナリオを確率で引いて混ぜ、三連複確率を出す。前半シナリオの確率の較正も必要で、フェーズ3のゲート判定で回収率を確認する。

### フェーズ3: 三連複 EV のゲート判定（2026-10-17 責務外に変更。LLM 側の担当）

- EV = 改善後の三連複確率 × 三連複オッズ（発走前スナップショット）。
- 戦略は単純に「EV ≥ 閾値の三連複を全部買う」。閾値は事前に少数（例: 1.0 / 1.2 / 1.5）に絞り、多重比較を避ける（ADR-0009 の教訓）。
- walk-forward プール bootstrap CI の下限が 100% を超えるかで判定。超えなければ ADR 化してここで止める。

### フェーズ4: 買い目の組み合わせ・資金配分（2026-10-17 責務外に変更。LLM 側の担当）

- 同じレースの三連複は排他的な結果なので、多点ケリー（排他的結果の Kelly 配分）で各点の賭け金を決める。フラクショナル Kelly 前提。
- 点数の上限、1レースあたりの予算上限、パリミュチュエルのオッズ低下（自分の投票による低下。少額なら無視できる）を制約として入れる。
- 出力: レースごとの推奨買い目リスト（組・賭け金・EV・確率）。

## 人気帯別の較正（2026-10-17）

`python -m predictor.main calibration-by-popularity`（テスト期間 21,575レース、10場、標準 split）の結果。人気は評価の切り口にだけ使っている。

| 人気帯 | 勝率 予測 | 勝率 実際 | 3着内 予測（place_prob） | 3着内 実際 |
|---|---|---|---|---|
| 1番人気 | 19.2% | 33.5% | 44.8% | 65.0% |
| 2-3番人気 | 13.4% | 16.5% | 35.0% | 47.1% |
| 4-6番人気 | 8.6% | 7.2% | 24.9% | 27.4% |
| 7-9番人気 | 5.3% | 2.9% | 16.5% | 13.3% |
| 10-12番人気 | 3.4% | 1.2% | 10.9% | 6.3% |
| 13番人気以下 | 2.0% | 0.43% | 6.5% | 2.5% |

- モデルの確率は全体に平らすぎ、人気薄を大きく過大評価している（すべての人気帯でずれは有意）。市場（単勝オッズ）の勝率はどの人気帯でもほぼ正確。
- 人気薄の1着だけを選んで買う使い方には最も危ない方向のずれ。
- 原因の候補: (1) 市場が持っていてモデルに無い情報（オッズは特徴量に入れない方針なので埋めきれない）、(2) 馬ごとの isotonic 較正のあとレース内で割り戻す確率の作り方で平らになっている（直せる余地あり）。まず (2) をレース単位の鋭さ調整で確かめる。

## モデルが市場に負けている箇所（2026-10-19）

`python -m predictor.main gap-analysis`（テスト期間 21,443レース、オッズなしの P3 と単勝オッズの市場を比較。差は「モデル − 市場」で正ならモデルが負けている）の結果。

- 全体: 勝率の対数尤度 モデル 2.19 / 市場 1.92、3着内率の logloss モデル 0.446 / 市場 0.410。
- 差はほぼすべての区切りに均等に広がっている（クラス・芝ダート・距離・頭数・馬場・開催場のどれで区切ってもレース単位で 0.22〜0.31）。特定のレース種別ではなく、馬の能力の見積もり全般で負けている。
- キャリアの浅い馬で差が最も大きい: 新馬戦 0.374（平均の約1.4倍、全体の差の12%）、初出走馬の3着内率 0.058（平均約0.036の1.6倍）、2歳馬 0.048。過去の成績が無い馬について、市場は調教・血統・厩舎の評判などを使っているがモデルには材料がほとんど無い。
- 人気馬の過小評価が大きい: 3着内率の差は1番人気 0.073、2-3番人気 0.064 で、この2つで全体の差の約4割。
- G1 はレース単位で 0.57 と最大だが、145レースしかなく全体への影響は1.4%。
- 次の打ち手の候補: (1) 相手の強さを考慮した馬の能力レーティング（Elo や時系列の Plackett-Luce。全レースに効き、人気馬の過小評価にも効く見込み）、(2) 初出走・キャリアの浅い馬向けの特徴量（母の他の産駒の成績、調教師の新馬戦成績など）。

## 当面の進め方（2026-10-12 合意）

- 案D（逃げ馬の崩れ・展開シナリオ）はいったん保留。まず崩れを考慮しない現行 PL と案A・B で、三連複対数尤度と回収率がどれくらい出るかを測ってから次を決める。
- 回収率は、確率だけで買い目を決めるルール（確率上位 N 点など）と、推定三連複オッズを使った EV ルールの両方を測る。どちらも回収額は `payoffs` の実配当で計算する。
- タスクは `todo.md` の「三連複のベースライン測定」を参照。
