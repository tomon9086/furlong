# 地方競馬モデルの分離（検討メモ）

## 発端

回収率評価における「勝ち馬oddsのnull」調査（2026-08-11）で、以下が判明した。

1. `race_results.odds` が2026/04/27頃を境に新規レースでほぼ100%欠損している。
2. 同時期に `races.venue` の対象範囲が中央競馬4場（中山・東京・京都・中京）から、
   中央競馬の残り4場（阪神・函館・小倉・福島）と地方競馬14場を含む計18場へ急拡大していた
   （それ以前は該当venueのレースが1件もDBに存在しない）。
3. 上記2点は同時期に発生しており、意図しないスクレイパー変更が原因と推測される
   （根本原因は別途調査・修正する。[docs/todo.md](../todo.md) 参照）。
4. (2) の新規venueは現行の学習・較正データ（`split_by_date` で train は〜2017年、
   val は〜2020年で終わる）に一度も出現しないため、テスト期間で初めて評価される
   cold-start状態になっている。

上記の調査を機に、「地方競馬の予想もしたい」という新規要望が生まれた。
本ドキュメントはそのモデル構成の検討記録。

## 検討した選択肢

### A. 別モデルに分離する（採用）

- 中央競馬モデルはそのまま維持し、地方競馬専用の別モデル・別特徴量パイプラインを新設する。
- Pros:
  - 中央競馬モデルの学習データ分布を汚さない（地方競馬の混入によるノイズ・分布シフトを回避）。
  - 地方競馬特有の前処理（クラス表記・馬場特性等）を独立に設計できる。
  - 地方競馬データはまだ数ヶ月分しかなく、統合しても現状は学習にほぼ寄与しない。
- Cons:
  - 特徴量パイプライン・学習/評価コードの一部を並走させる必要があり保守対象が増える
    （スクレイパー・DBスキーマ・評価関数などの共有可能な部分はそのまま流用する）。

### B. 既存モデルに統合する（不採用）

- 地方競馬データも遡及スクレイピングして単一モデル・単一パイプラインで扱う。
- Pros: データ量が増え、jockey/trainer等の表現学習が共有できる可能性。
- Cons:
  - 地方競馬の過去データ遡及スクレイピングは中央競馬（1995年〜）と同規模になりうる大工事。
  - `_extract_class_level`（[preprocessing.py](../../predictor/predictor/preprocessing.py)）
    は中央競馬のクラス表記（「1勝クラス」「500万下」等）専用の正規表現で、地方競馬の
    クラス体系（C1等）に対応していない。統合すると地方競馬行の `class_level` が
    軒並みNaN化し、パイプライン全体に歪みを持ち込むリスクがある。
  - 帯広(ば)＝ばんえい競走は、そりを牽引する完全に別競技（走破タイムが分単位、
    「着順」の意味も通常の競走と異なる）で、`is_win`/`finish_time_sec` 等の前提が
    そのまま流用できない。統合するとしても最初に除外すべき対象。
  - 中央・地方で騎手/調教師プールがほぼ別であり、統合による転移学習の恩恵は限定的。

## 決定

**A. 別モデルに分離する** を採用（2026-08-11）。

## 補足: netkeibaの地方競馬 歴史データの有無

「そもそも古い地方競馬データがnetkeibaで公開されていないのでは」という懸念があったため、
2026-08-11にスポットチェックした。

- `db.netkeiba.com/race/list/20050115/` に大井・川崎・船橋・浦和の地方競馬セクションが存在し
  各11レース掲載を確認。
- 実際に1レース（大井, `/race/200553011501/`）を取得したところ、着順・単勝オッズ・走破タイムを
  含む完全なレース結果データが存在した。

→ 少なくとも大井・川崎・船橋・浦和は2005年時点で完全なデータが存在する。**ただし1日・1場の
スポットチェックのみ**であり、以下は未確認（別モデル分離後、過去データ遡及を検討する際に要調査）。

- 残り10場（門別・帯広・水沢・盛岡・金沢・笠松・名古屋・園田・高知・佐賀 等）の遡及可能な深さ
- 各場でどこまで古い年まで遡れるか（JRAの1995年と同水準かは不明）
- oddsフィールドが欠損なく通しで取れるか（今回確認できたのは1件のみ）
