# ADR-0031: 複勝推奨の選出を常にちょうど上位3頭に固定

- Status: Accepted
- Date: 2026-09-20

## Context

`predictor/predictor/output.py` の複勝推奨選出は `place_prob` を `rank(ascending=False, method="min")` で順位化し `rank <= 3` を採用していた。Isotonic Regression による較正（[ADR-0006](./0006-isotonic-calibration.md)）はステップ関数であり、複数馬の生スコアが同じ較正区間（プール）に入ると `place_prob` が完全一致する。3位と4位以降がこのtieに巻き込まれると `method="min"` の性質上、意図した3頭を超えて選出される。

過去の全予測ログ（57レース）を集計したところ、複勝推奨頭数が3頭を超えていたレースが10件（17.6%）あり、最大6頭選出されたケースも1件確認した。これは想定外の賭け対象数増加であり、資金配分・回収率評価の前提を崩す。

## Decision

複勝推奨の選出方法を「`place_prob` 降順ソートし先頭3頭を採用（同値は元の順序でtie-break）」に変更する。tie自体（较正の縮退）は解消しないが、選出頭数は常にちょうど3頭に固定される。

過去テストセット（157,477行、11,367レース）でのペアードbootstrap検証（race-level resampling, n_boot=10,000）では、この変更による複勝回収率への影響は統計的に有意ではなかった（点推定 +0.17pt、95%CI [-0.24pt, +0.56pt]、CIが0を跨ぐ）。したがって本変更はEV改善策ではなく、「上位3頭」という設計意図とのズレを是正する正当性修正として採用する。

## Consequences

- 複勝推奨頭数が常に3頭になり、overflow（4〜6頭選出）が解消される（過去データでは該当17.6%のレースが影響を受けていた）。
- 複勝回収率（3頭均等ベット想定）への統計的に有意な影響はない（改善も悪化もしない）。
- tie自体（isotonic較正の縮退）は残る。根本対応は [ADR-0032](./0032-sigmoid-place-calibration-rejected.md) で検討し不採用とした。
